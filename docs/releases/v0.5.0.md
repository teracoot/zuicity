# Zuicity v0.5.0

Zuicity v0.5.0 strengthens SOCKS5 interoperability, Linux UDP offload safety,
connection reuse, and production validation while retaining wire compatibility
with upstream Juicity.

## Highlights

- Added structured server-side SOCKS5 outbound routing for TCP and UDP,
  including authentication, DNS targets, UDP ASSOCIATE, setup timeouts, and
  session-local failure recovery.
- Reused one authenticated QUIC connection across TCP forwarders, UDP peers,
  SOCKS5 clients, and HTTP CONNECT clients, with transparent reconnect after a
  stale or closed connection.
- Kept Linux UDP GSO off by default and explicitly opt-in with
  `ZUICITY_ENABLE_GSO=1`.
- Hardened GSO behavior so handshake packets are never segmented and
  `EINVAL`/`EIO` falls back immediately to lossless ordinary datagrams for only
  the affected destination.
- Retained receive-side GRO where supported, with plain-receive fallback and
  `ZUICITY_DISABLE_GRO=1` control.
- Applied configured BBR, CUBIC, or NewReno controllers throughout client,
  server, DAE, and nested outbound paths. BBR remains the default and selected
  release profile.
- Improved concurrent stream handling, cancellation, timeout isolation, proxy
  error classification, and shutdown cleanup.

## SOCKS5 outbound

The server can route accepted Juicity destinations through one upstream SOCKS5
proxy without changing direct mode:

```json
{
  "outbound": {
    "type": "socks5",
    "server": "127.0.0.1",
    "server_port": 10808,
    "username": "optional-user",
    "password": "optional-password"
  }
}
```

TCP uses SOCKS5 CONNECT and UDP uses UDP ASSOCIATE. DNS resolution, connection,
method selection, authentication, and proxy negotiation share a bounded setup
deadline. An unreachable or silent proxy fails only the affected session and
does not terminate the server. Existing `dialer_link` configuration remains
supported; conflicting `outbound` and `dialer_link` values fail validation.

See [`docs/socks5-outbound.md`](../socks5-outbound.md) for configuration and
environment overrides.

## Fresh four-product benchmark

All four implementations were freshly executed in the v0.5.0 campaign. No
comparator result in this table was copied from an earlier run.

The campaign interleaved eight treatments using a complete Williams square:
Zuicity v0.5.0, stock Go v0.5.0, repaired full-GSO Go v0.5.0, and the latest
official `juicity-rs`, each under its defined GSO-on and GSO-off treatment. It
completed eight balanced rotations, 64 accepted rows, and 640 accepted
throughput transfers. Every row included 60 fresh-connect RTT samples, 60
persistent RTT samples, two warmups, and 10 fresh 512 KiB send-plus-full-echo
transfers.

| Implementation | Effective GSO | Throughput | Persistent RTT | Combined HWM |
| --- | --- | ---: | ---: | ---: |
| **Zuicity v0.5.0** | full on | **1149.34 Mbps** | **0.381 ms** | **16,602 KiB** |
| Stock Go v0.5.0 | shipping client-off/server-on | 694.76 Mbps | 0.513 ms | 38,400 KiB |
| Repaired Go v0.5.0 | full on | 995.04 Mbps | 0.508 ms | 38,848 KiB |
| Latest `juicity-rs` | Quinn default on | 17.74 Mbps | 27.711 ms | 41,530 KiB |
| **Zuicity v0.5.0** | native off | **764.13 Mbps** | **0.386 ms** | **16,578 KiB** |
| Stock Go v0.5.0 | native off | 657.35 Mbps | 0.526 ms | 38,398 KiB |
| Repaired Go v0.5.0 | native off | 694.11 Mbps | 0.503 ms | 38,336 KiB |
| Latest `juicity-rs` | externally controlled off | 5.14 Mbps | 27.495 ms | 31,358 KiB |

Within matched rotations, Zuicity's median paired throughput change was:

- Versus stock Go: `+71.76%` with GSO on and `+12.16%` with GSO off.
- Versus repaired Go: `+10.60%` with GSO on and `+2.99%` with GSO off.
- Versus latest `juicity-rs`: `+4257.25%` with GSO on and `+13725.21%`
  with GSO off.

All eight pre-measurement GSO syscall probes passed. Every on treatment showed
the expected segmented sends, and every off treatment showed zero
`UDP_SEGMENT` attempts.

The four Go comparisons did not reach a `0.05` one-sided sign-test threshold
with eight rotations. Candidate throughput was variable, particularly in the
GSO-on treatment. Six `juicity-rs` GSO-on attempts timed out and were preserved
as rejected evidence; complete replacement rows passed under the unchanged
five-attempt rule.

This was a single-host WSL2/Linux `veth` comparison using a common 512 KiB
payload. It is not WAN evidence and is not the canonical 4 MiB profile, because
the tested official `juicity-rs` build could not reliably complete the larger
payload. See the
[`v0.5.0 four-product report`](../benchmarks/v0.5.0-four-product-512k.md)
for connect RTT, CPU, hashes, paired inference, retries, and limitations.

## Matched Hysteria2 benchmark

A separate two-product campaign freshly executed Zuicity v0.5.0 and official
Hysteria2 v2.11.0 under matched BBR and GSO treatments. Each arm used five
alternating pairs with 60 fresh-connect RTT samples, 60 persistent RTT samples,
five warmups, and 100 fresh 4 MiB send-plus-full-echo transfers per row.

| GSO treatment | Zuicity v0.5.0 | Hysteria2 v2.11.0 | Zuicity pair wins |
| --- | ---: | ---: | ---: |
| Off versus off | **84.76 Mbps** | 80.75 Mbps | **5/5** |
| On versus on | **180.91 Mbps** | 108.17 Mbps | **5/5** |

Zuicity's median paired advantage was `7.66%` off/off and `66.80%` on/on. This
campaign is independent of the four-product WSL2 campaign; its samples and
results were not pooled with that experiment.

## Validation

The v0.5.0 qualification included:

- Full workspace, all-target, and doctest suites on native Windows and WSL
  Linux.
- Vendored Quinn-proto's 265 unit tests and three doctests on both platforms.
- Ignored Quinn receive-window stress tests and a 50-connection, approximately
  50 MiB checksum-validated transfer on both platforms.
- Five repeated connection-reuse, concurrency, lifecycle, and high-pressure
  rounds on both platforms.
- A fresh 30-minute WSL soak covering 9,092 waves, 36,368 TCP relays, and
  36,368 UDP relays, with `1.3314x` RSS growth and `+2` file descriptors.
- Authenticated external interoperability with `serjs/go-socks5-proxy`,
  including invalid-password rejection.
- All 7,168 generated upstream differential-oracle cases on Windows and Linux.
- Live upstream Go Juicity v0.5.0 interoperability with system-root TLS
  validation and end-to-end traffic.
- Validation of 18 platform archives, the source archive, and all
  MD5/SHA-1/SHA-256/SHA-512 digest sidecars.

## Upgrade notes

- Direct egress remains the default when neither `outbound` nor `dialer_link`
  is configured.
- GSO remains disabled unless `ZUICITY_ENABLE_GSO=1` is explicitly set.
- `ZUICITY_DISABLE_GSO=1` takes precedence when both GSO variables are set.
- GRO remains enabled where supported; set `ZUICITY_DISABLE_GRO=1` to force
  ordinary receives.
- Existing Juicity configuration and the `run -c <config.json>` interface remain
  compatible.
- Back up binaries and configuration, verify staged hashes and TCP/UDP traffic,
  and retain the previous known-good artifact for rollback.

The complete release gate and deployment procedure is in
[`docs/production-readiness-testing.md`](../production-readiness-testing.md).
