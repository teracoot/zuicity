# Zuicity v0.4.0, Go Juicity, and latest juicity-rs

This is one matched local-veth campaign containing four products:

- Zuicity v0.4.0 benchmark-winning artifact
- Stock upstream Go Juicity v0.5.0
- Repaired Go Juicity v0.5.0 with connected-UDP OOB preservation
- Latest official `github.com/juicity/juicity-rs` build

The campaign started on 2026-07-31 UTC (2026-08-01 local time). It is a complete
balanced common-workload comparison, but it is not the canonical 4 MiB standard
profile because latest `juicity-rs` cannot complete that payload reliably.

## Method

- Topology: two fresh Linux network namespaces joined by a veth pair.
- Host: WSL2 Ubuntu 24.04.4, Linux 6.6.87.2, AMD Ryzen 7 5800X.
- Design: one complete eight-treatment Williams square.
- Rotations: 8.
- Accepted measured rows: 64.
- Rejected attempts retained: 1.
- Per row: 60 fresh-connect RTT, 60 persistent RTT, and 10 throughput samples.
- Throughput operation: fresh TCP connection, 512 KiB send, then full echo receive.
- Warmups: 2 transfers per row.
- Accepted throughput transfers: 640.
- CPU affinity: server 12,14; client 8,10; driver 4; echo target 2.
- GSO probes: all eight passed before measured rows.
- Inference unit: one accepted rotation-level row median.

## Mode controls

- Zuicity on: `ZUICITY_ENABLE_GSO=1`; off: `ZUICITY_DISABLE_GSO=1`.
- Stock Go on is its shipping default: client GSO is off while server GSO is on.
- Repaired Go on: empty `QUIC_GO_DISABLE_GSO`; off: `QUIC_GO_DISABLE_GSO=true`.
- Latest `juicity-rs` on uses the unmodified Quinn default.
- `juicity-rs` has no native GSO-off switch. Its off treatment uses the unchanged
  official binaries plus a hash-pinned external preload that denies the
  `UDP_SEGMENT` capability probe on both roles.

The traced probes recorded successful `UDP_SEGMENT` sends for every on treatment
and zero attempts for every off treatment. The `juicity-rs` off logs also record
the external capability denial on both client and server.

## Qualifications and limitations

- Latest official `juicity-rs` timed out on a single 4 MiB transfer after 120
  seconds despite 141 successful `UDP_SEGMENT` sends. It therefore cannot join
  the existing canonical 4 MiB campaign.
- An untraced latest-`juicity-rs` qualification completed the proposed
  60/60/10 contract at 512 KiB, so every product used that common payload.
- One measured `juicity-rs` GSO-on warmup timed out in rotation 5. The failed
  attempt is retained in `rejected.jsonl`; attempt 2 passed the full row contract.
- Latest `juicity-rs` throughput was highly variable in both modes. Its row-level
  CV was 155.85% on and 136.96% off, so absolute medians should be read together
  with the paired wins and raw rotation values.
- Candidate throughput also had high row-level CV: 34.25% on and 42.35% off.
- Background CPU monitoring was available for every accepted row. WSL exposed
  neither CPU-frequency nor thermal telemetry.
- `canonical_balanced_campaign` is false because the standard profile payload and
  sample count were overridden, even though position and first-order carryover
  balance both passed.
